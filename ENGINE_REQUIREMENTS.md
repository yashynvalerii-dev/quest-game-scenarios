# Quest Game — реестр технических вопросов сценарного отдела

Область: контракт Node-RED → конвертер → валидатор → лаборатория Quest Game. Этот реестр **не является ТЗ разработчика** и не изменяет движок. Техническая реализация принадлежит главному разработчику; владелец утверждает изменения поведения игры.

## Правила
- Единая точка входа для технических вопросов; к каждому пункту — статус, проверка, ссылка на первичный артефакт, версия/коммит при подтверждении.
- Статусы: наблюдение → воспроизведение → вопрос разработчику → согласовано → реализовано → проверено. Сценарный тест не равен верификации кода движка.
- Перед созданием нового требования проверять текущий формат квеста, документацию палитры и лаборатории главного разработчика. Не дублировать существующий механизм.
- Детали скрытых сюжетов остаются в приватном репозитории, публично фиксируются только обезличенные технические проблемы.
- Корпоративная почта dev-hub — для согласований, критических проблем и итогов, а не для каждого промежуточного обсуждения.

## QER-001 — Два варианта qg-choice с общим узлом назначения
**Статус:** подозрение, минимальное воспроизведение ожидает лабораторной проверки.

**Наблюдение:** в прежнем сценарии «Электричество в убежище» конвертер/валидатор лаборатории сообщил «У выбора должно быть хотя бы два варианта», хотя конфигурация Node-RED содержала два правила выбора и два выхода к одному следующему заданию. Причина не установлена. Диагностические JSON сами по себе не показывают итоговую нормализованную структуру вариантов.

**Контрольный тест:** на вкладке 08 Quest Game Logic Test начать с принятого квеста «Риск или победа» с одной задачей и финишем, затем добавить qg-choice с двумя выходами к разным финишам, и только после успешной проверки соединить оба выхода с одним финишем. После каждого шага Deploy, экспорт, импорт, лабораторный прогон, точный текст ошибок.

**Ожидается:** два независимых варианта сохраняются и отображаются даже при одинаковой целевой вершине; каждому варианту можно назначить отдельное действие.

**Основание:** отчет пользователя о лаборатории 2026-11-26 и диагностические файлы `quest-game-scenarios-private/DIAGNOSTICS/node-red-full.json`, `node-red-latest.json` (снимки могут обновляться). Регрессионный тест не завершен. Не менять контракт без проверки и решения главного разработчика.

## QER-002 — Пользовательские подписи вариантов выбора
**Статус:** наблюдение; причина не установлена.

**Наблюдение:** Node-RED qg-choice имел подписи правил «вариант 1» и «вариант 2», но экран лаборатории показал кнопки `f1` и `f2` — ID целевых финалов. В лаборатории обе ветви отдельно завершались (победа/проигрыш).

**Ожидается:** уточнить у главного разработчика контракт представления подписей выбора; при предусмотренных пользовательских подписях они должны доходить до игрового интерфейса. Не называть это доказанным дефектом, пока не установлен фактический контракт.

## QER-003 — Минимальный валидный квест и обязательная задача
**Статус:** проверено в лаборатории 2026-11-26.

**Факт:** `qg-quest → qg-finish` — импорт с одной ошибкой «Добавьте хотя бы одно задание». После добавления `qg-task` получено «Квест проходим, финал достижим» (1 задание, 2 шага, 1 переход). Это фактическое правило проверенной версии, а не запрос на изменение.

**Примечание:** использованная задача сохранила GPS-проверку и координаты из редактора; её прохождение было вручную проверено в виртуальной лаборатории, не на физическом GPS.

## Текущая граница
Тест с разными финалами подтверждён скриншотами пользователя: стартовое задание, выбор, два разных финала. Флаг `money`/счётчик 100 в конфигурации `qg-quest` присутствовал, но реальное списание 100 ещё не проверялось. Значение «Баллы: 0» не эквивалентно значению счётчика `money`.

Следующий шаг: проверить оба выхода `qg-choice` на **один** `qg-finish` и сохранить результат, прежде чем добавлять действие изменения `money`.
